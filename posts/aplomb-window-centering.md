# Aplomb：把 Windows 窗口真正摆到正中

---

## 从一个看似简单的问题开始

把窗口移到屏幕中央，听起来只需要几行坐标计算。但 Windows 的窗口矩形并不总等于人眼看到的边界：`GetWindowRect` 会把 DWM 绘制的不可见阴影算进去，直接拿它做居中，结果往往会在视觉上偏左或偏上。

**Aplomb · 从容** 就从这个细节出发。它是一款面向 Windows 10 / 11 的轻量窗口居中工具，常驻系统托盘，用三个全局快捷键完成当前窗口、指定窗口或全部窗口的整理。

![Aplomb 深色设置界面](https://raw.githubusercontent.com/StarsOfDeduce/Aplomb/main/screenshots/general-dark.png)

项目名 Aplomb 在法语中有“沉稳自若”的含义，在建筑语境中也指向铅垂与对中。这个名字恰好概括了它的目标：不改变工作流，只在需要时把窗口摆正。

---

## 像素级居中的实现

Aplomb 不只使用 `GetWindowRect`，还会通过 `DwmGetWindowAttribute` 读取 `DWMWA_EXTENDED_FRAME_BOUNDS`，得到真实可见边框，再把不可见阴影的偏移补回最终坐标。

这套计算还有两个容易忽略的约束：

1. 每次操作都重新读取窗口几何，避免连续触发后因为旧坐标而产生漂移；
2. 通过 `MonitorFromWindow` 找到窗口所在显示器，按对应工作区居中，而不是默认使用主显示器。

在项目记录的测试条件下，这套算法达到了 0 像素的可见边框对齐误差。设置页也保留了“像素级修正”开关，方便直接比较两种算法。

## 三个动作与一个选择器

默认快捷键刻意保持精简：

| 快捷键 | 动作 |
| :--- | :--- |
| `Ctrl + Alt + C` | 居中当前窗口 |
| `Ctrl + Alt + X` | 打开选择器，居中一个或多个窗口 |
| `Ctrl + Alt + B` | 居中全部符合条件的窗口 |

选择器采用类似 Alt-Tab 的缩略图布局，可以按窗口标题或进程名过滤，也支持方向键、Enter、Esc 和 `Ctrl + 点击` 多选。缩略图尚未准备好时，界面会先显示程序图标，不让图像抓取阻塞主要操作。

![Aplomb 窗口选择器](https://raw.githubusercontent.com/StarsOfDeduce/Aplomb/main/screenshots/picker-dark.png)

全局快捷键由 Win32 `RegisterHotKey` 驱动，并使用 `MOD_NOREPEAT` 抑制按住按键时的重复触发。Qt 原生事件过滤器只处理目标 Windows 消息，并按消息标识与时间去重；因此工具不需要持续轮询窗口列表。

## 不让异常窗口拖住整个工具

桌面程序不能假设其他进程永远响应。读取外部窗口标题时，同步消息可能被已经卡死的应用拖住。Aplomb 会先用 `IsHungAppWindow` 识别无响应窗口，并通过带 50 毫秒超时的 `SendMessageTimeout` 获取标题；超时后直接跳过，而不是等待目标进程恢复。

批量居中时，工具还会避开：

- 全屏或最大化窗口；
- Windows 外壳和自身界面；
- 用户加入忽略列表的程序；
- 已经无响应、不能安全读取状态的窗口。

忽略项既可以手动指定 exe，也可以从当前正在运行的窗口中选择。这样做比让用户寻找安装路径更贴近日常操作。

## 小工具也需要完整的工程边界

Aplomb 是本地工具，但“本地运行”本身不是安全结论。项目把权限、配置和发布链路分别收紧：

- 安装器使用按用户安装，写入 `%LOCALAPPDATA%\Programs\Aplomb`，声明 `RequestExecutionLevel user`，不请求管理员权限；
- 开机启动只写当前用户的 `HKCU\...\Run`，不会修改系统级启动项；
- 配置先写临时文件，再用原子替换更新，降低中途退出造成配置损坏的概率；
- 运行和构建依赖都固定版本，并在锁文件中加入哈希校验；
- v1.0.1 发布页同时提供独立的 `SHA256SUMS.txt`，便于校验下载文件。

根据 v1.0.1 的发布记录，这次更新完成了依赖漏洞审计、27 项界面冒烟测试、安装版与便携版启动验证，以及发布物敏感信息扫描。这里记录的是该版本发布时的验证结果，不代表未来版本可以跳过复查。

## 性能取舍：先测量，再删掉不必要的东西

项目测试记录显示，在 1080p、7 个窗口的环境下，托盘待机约 50.9 MB，选择器展开约 80 MB，连续开关 14 次后内存不再持续增长。这些数字不是所有设备上的保证，但能说明优化过程有明确基线。

其中一些改动很反直觉：

- 不为每个 Qt 控件单独指定字体，避免重复解析字体回退链；
- 避免使用默认字体缺失的特殊符号，减少额外符号字体加载；
- 关闭选择器时显式处理延迟销毁事件，避免反复打开后累积对象；
- 仅在用户触发快捷键时枚举窗口，不设置后台轮询定时器。

对这种常驻型小工具来说，克制往往比堆叠功能更重要。

## 安装与已知限制

截至本文发布，最新稳定版为 **v1.0.1**，提供按用户安装版和便携版：

- 安装版适合长期使用，可选择桌面快捷方式与开机启动；
- 便携版把配置保存在程序旁的 `data\` 目录，适合随身携带；
- 两种版本使用同一个单实例机制，不建议同时运行。

它目前只支持 Windows 10 / 11；全屏独占窗口不会被移动；少数 Electron 或硬件加速窗口无法通过 `PrintWindow` 取得画面时，选择器会改用程序图标占位。
